# フィード閲覧機能のテスト観点

## 目的

初めて利用するユーザーが説明を確認したうえで、フィードを3分間利用できることを確認する。

また、再読み込みや繰り返し操作によって、利用時間が短くなったり、不正に延長されたりしないことを確認する。

## 背景

フィードは、タスク完了後に3分間だけ利用できる。

以前は、初回の説明モーダルが表示された時点でカウントダウンが始まっていたため、ユーザーが説明を読んでいる間にも利用時間が減っていた。

現在は「OK」を押した後にカウントダウンを開始するようにしているが、同じ不具合の再発を防ぐため、カウント開始のタイミングを重点的に確認する。

また、初回説明を確認したかどうかをブラウザのlocalStorageに保存しているため、同じブラウザを複数のアカウントで利用した場合や、同じアカウントを別の端末で利用した場合に、表示状態が一致しない可能性がある。

今後は、初回説明の確認状態をアカウントごとに管理する。

## 重点的に確認するリスク

- 説明を読んでいる間に、3分間の利用時間が減る
- 初めて利用するアカウントに説明が表示されない
- 説明を確認済みのアカウントに、再び説明が表示される
- 再読み込みすると残り時間が3分に戻る
- 「OK」を複数回押すと利用時間が延長される
- 3分経過後もフィードを利用できる
- 画面に表示される時間と、サーバーで管理する時間がずれる

## テスト観点

### 利用者の状態

- 初めてフィードを利用するアカウント
- 初回説明を確認済みのアカウント
- 同じブラウザで別のアカウントに切り替えた場合
- 同じアカウントで別のブラウザや端末を利用した場合
- 一度ログアウトして再ログインした場合

### 説明モーダル

- 初回利用時に表示されること
- 説明を確認済みの場合は表示されないこと
- 「OK」を押すとモーダルが閉じること
- 「OK」を複数回押しても、処理が重複しないこと
- 初回説明の確認状態がアカウントごとに保存されること

### カウントダウンの開始

- 説明モーダルの表示中は開始されないこと
- 「OK」を押した後に3分から開始されること
- 説明を確認済みの場合は、フィードを開いた適切なタイミングで開始されること
- 「OK」を再度押しても利用時間が延長されないこと

### 閲覧中の時間管理

- カウントダウンが正しく減ること
- 再読み込みしても3分に戻らないこと
- フィードを閉じて再び開いても残り時間を引き継ぐこと
- 別のブラウザや端末でも、サーバー側の残り時間を引き継ぐこと
- 画面とサーバーで残り時間が大きくずれないこと

### 閲覧時間の終了

- 3分経過後にフィードを利用できなくなること
- 時間終了の案内が表示されること
- 時間終了後は、いいねやコメントなどの操作ができないこと
- 新しいタスクを完了すると、再びフィードを利用できること

### 通信エラー

- 「OK」を押した際に通信が失敗した場合
- フィードの取得に失敗した場合
- 通信が遅い状態で「OK」を複数回押した場合
- エラー後に再度操作できること

## 優先度

優先度が高い観点は次のとおり。

1. 説明モーダルの表示中はカウントダウンを開始しない
2. 「OK」を押した後に3分から開始する
3. 初回説明の確認状態をアカウントごとに管理する
4. 再読み込みしても残り時間をリセットしない
5. 繰り返し操作によって利用時間を延長できない
6. 3分経過後はフィードを利用できない

## 今後の対応

このテスト観点をもとに、事前条件、操作手順、期待結果を記載したテスト仕様書を作成する。

その後、既存の単体テスト、バックエンドテスト、E2Eテストで確認できている範囲を調べ、不足しているテストを追加する。
